# Support

## Where to ask for help

Use GitHub Issues for reproducible bugs and bounded feature requests. Choose the provided issue form so maintainers receive the environment, version, acceptance criteria, and sanitized diagnostics needed to act on the report.

Before opening an issue, check `README.md`, `QUICKSTART.md`, `ARCHITECTURE.md`, `ROADMAP.md`, `exec-planning.md`, and existing issues/pull requests.

## Security issues

Do **not** disclose suspected vulnerabilities in a public issue. Follow `SECURITY.md` and the repository Security policy to report them privately.

## What support covers

Supported requests include installation and packaging problems, CLI/API behavior, CodeAgent/tool defects, provider-routing integration problems, MCP/hooks/skills/plugin integration defects, SDK compatibility, Docker/Helm deployment problems, and CI/release regressions.

## What to include

Provide the zcoder version or commit SHA, operating system, Python version, relevant provider/runtime, minimal reproduction steps, expected versus actual behavior, and sanitized logs. Never include API keys, OAuth tokens, private prompts, customer data, or production secrets.

## Production operations

For production deployment incidents, include health/readiness state, deployment version, rollback status, sanitized structured logs, and whether the incident affects identity, authorization, tenancy, filesystem, network, or data durability boundaries.
